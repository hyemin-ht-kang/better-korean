# 한국어 윤문 룰 (플러그인 표준)

이 파일이 better-korean 플러그인의 표준 룰 원본이다. 프로젝트 `.claude/better-korean-rules.md` 나 개인 `~/.claude/better-korean-rules.md` 가 있으면 이 룰에 병합된다 (형식은 이 파일과 같게 쓴다).

한국어 산출물(문서, 테이블·컬럼 comment, 분석 보고서, PR 본문)은 사람과 후속 AI 에이전트가 그대로 활용하는 자산이다. 기준은 하나다: 처음 읽는 사람과 AI 에이전트가 문장만 보고 의미를 특정할 수 있어야 한다. 낯선 문어체 압축어·임의 번역어는 반 줄 길어져도 예시가 붙은 풀어 쓴 표현 + 원어 병기로 쓴다.

## 금지어 목록 (grep 패스 대상)

`금지어 → "대체 표현"` 형식. 스킬의 grep 패스가 이 목록을 파싱해 기계적으로 검색한다.

### 접두 조어 (미-/무-/비-/역-/저- 등)

서술을 접두사로 명사 하나에 압축하지 않고, "~가 없다 / ~되어 있지 않다" 서술로 풀어 쓴다.

- 미내장 → "정제가 내장되어 있지 않은"
- 무영향 → "값이 달라지지 않는다"
- 미적재 → "적재되지 않은"
- 역반영 → "역으로 반영"
- 비자명 → "코드만으로(설명 없이는) 알 수 없는"
- 저신뢰 → "신뢰도가 낮은"

예외: 이미 익숙하게 널리 쓰여 설명 없이 뜻이 통하는 단어(미확인, 비정상 등)와 `[미확인]`/`[추정]` 미해결 마커.

### 문어체 압축어

- 축자 → "문자 그대로"
- 획정 → "범위를 정한다/경계를 긋는다"
- 봉투 → "감싸는 구조/래퍼(wrapper)"
- 계상 → "집계된다/잡힌다"
- 정본 → "원본 / 기준 문서 / 참조 대상 문서 / 가장 권위 있는 문서 / SSoT인 ~" (문맥에 따라 고른다: 사본과 대비하는 자리면 "원본", 값을 확인할 곳을 가리키면 "기준 문서"나 "SSoT인 ~에서 확인한다", 여러 사본 중 어느 것이 권위를 갖는지 말하는 자리면 "가장 권위 있는 문서")
- 재전사 → "옮겨 적다"
- 규약 → "룰/원칙"
- 병용 → "함께 사용한다/함께 활성화한다"
- 관철 → "(끝까지) 지켜진다"
- 실존 확인 → "실제로 존재하는지 확인"
- 과적용 → "범위를 넘겨 적용"
- 귀속 → "~에 속하는지 판정한다"
- 발화(이벤트가) → "기록된다/발생한다"
- 완형 → "완성된 형태"
- 오정렬 → "어긋난다"
- 전칭 → "'모든 ~' 단정"
- 비통일 → "~마다 다르다"
- 소관 → "~ 고유 / ~가 맡는다"
- 위임 → "~에 맡긴다 / 상세는 ~를 참조하게 한다"
- 준용 → "~와 같은 방식으로 한다 / ~ 패턴을 따른다"
- 물화 → "todo 항목으로 만들어지다/등재되다/옮겨지다"
- 실해 → "실제 피해/실질적인 손해"
- 갈린다(경로가) → "나뉜다 / 두 경로 중 하나를 적용한다"
- 정밀 → "상세" (표기의 세밀함을 뜻하는 "표기 정밀도"는 "표기 자릿수"로)
- 정밀화 → "상세하게 맞추다/다듬다"
- 자명 → "따로 설명하지 않아도(코드만 읽어도) 알 수 있다"
- 잣대 → "기준"
- 꼴(쿼리 꼴 등) → "형태/포맷" (부정적 뉘앙스가 있어 기술문서에 쓰지 않는다)
- 정착(표현이) → "이미 익숙하게 널리 쓰이는"
- 음차 → "발음만 한글로 옮겨 적기"
- 산문 → "사람이 문장으로 읽는 글/텍스트" (단순 치환보다 단어를 빼고 문장을 재구성하는 쪽이 자연스럽다)
- 층위 → "계층 / 읽기 경로 (무엇의 층인지 명시: 예 'comment 계층(테이블 comment 인지 컬럼 comment 인지)')"
- 실증 → "실제로 확인"
- 감사 → "점검" (audit 의미의 확립된 용어(감사 로그·보안 감사)와 인사말은 예외)
- 저작 → "작성" (저작권 등 합성어는 예외)
- 동형 → "같은 구조의" (수학 용어 isomorphic 의미는 예외)
- 정수(精髓) → "~를 가장 잘 보여주는" (은유 압축: 단순 치환보다 문장 재구성이 자연스럽다. 숫자 integer 의미는 예외)
- 군더더기 → "불필요한 문장 / 불필요한 반복" (구어 어감이 기술 문서에 맞지 않음)
- 자매 테이블 → "짝 테이블" (의인화 은유: 첫 등장에서 "짝 테이블(같은 데이터를 나눠 가진 상대 테이블)"처럼 정의를 붙이고, 이후 단독 사용)
- 가르다(판정: 가릅니다·가르세요·가름) → "판단하다 / 구분하다"
- 실측 → "실제 실행 결과로 확인 / 실제 측정값"
- 재산출 → "다시 산출"
- 신선도(데이터·기간이) → "최신 여부"
- 장부식 → "기호로 줄여 적은"
- 과대(~가 과대) → "너무 큼"
- 개조식 → "서술어를 생략한 축약 (어미)"
- 표면(검사·채점 표면이 늘다) → "검사 대상 (범위)"
- 연쇄(검사·확인) → "'~를 바꾸면 …까지 확인'처럼 동사형으로 풀어 쓰기"
- 처방(수정을) → "지시 / 수정안 제시"
- 동률 → "값이 같음 / 1위와 2위의 값이 같은 경우"
- 근소차 → "차이가 아주 작음"
- 배선 → "연결 / 등록" (예: "툴이 main 에이전트에 연결되어 있다", "fleet에 등록")
- 계측 → "트레이스/메트릭 기록" 또는 "측정 데이터 수집" (예: "계측 버그" → "트레이스 기록 버그", "계측이 빠져 있다" → "메트릭이 기록되지 않는다")

### 비유 표현

문서·사본·범위를 사람이나 사물의 동작에 비유하지 않고, 무엇이 어떻게 되는지 그대로 서술한다.

- 낡는다(문서·사본이) → "갱신되지 않은 채 남는다 / 원본이 바뀌어도 함께 바뀌지 않는다"
- 낡은 채 남았다 → "갱신되지 않은 채 남았다 / 예전 내용이 그대로 남았다"
- 덮는다(범위·경우를) → "커버한다 / 포함한다" (파일을 덮어쓴다(overwrite)는 예외)
- 죽은(참조·링크가) → "끊어진"
- 헐거워지다(테스트·기준이) → "변별력이 낮아지다 / 느슨해지다"
- 떠먹여 주다 → "그대로 알려 주다 / 미리 적어 주다"
- 억울한(오답·실패가) → "실제로는 맞는데도 오답/실패로 처리되는"
- 맨손으로 → "템플릿(도구) 없이 처음부터"
- 저격하다(지표·대상을) → "가리키다"
- 흡수하다(틀린 답·예외를 인정으로) → "~까지 인정해 주다 / ~까지 허용 범위에 넣다"
- 살아남다(지표·점수·테스트가) → "깨지지 않다 / 그대로 유지되다"
- 형제 셀 → "같은 표의 다른 셀"
- 곁가지(컬럼·항목 등이) → "핵심 결과에 쓰이지 않는 잉여 ~"

### 발음만 한글로 옮겨 적은 영어

영어 단어를 발음만 한글로 옮겨 적으면 처음 읽는 사람에게 뜻이 통하지 않으므로, 풀어 쓰고 필요하면 영문을 병기한다. 잘못된 발음 표기도 여기서 잡는다.

- 어노말리 → "비정상(anomaly)"
- 스킴 → "규칙/방식"
- 헝크 → "충돌 구간/변경 블록(hunk)"
- 라인리지 → "리니지(lineage)"
- idiom → "관례"
- 그레인 → "집계 단위"
- 스캐폴드(명사) → "템플릿 / 골격" (뼈대를 잡는 작업 동작을 뜻하는 "스캐폴딩"은 예외)
- 펜스 → 첫 등장에서 "펜스(fenced code block)"로 병기하면 이후 단독 사용 허용
- 예외: "파티션 프루닝(pruning)"은 확립된 기술 용어로, 원어를 병기하고 첫 등장에서 뜻을 풀면 허용

### 확립된 영어 용어의 축약 직역

영어 그대로 쓰는 것이 처음 읽는 사람에게 더 잘 통하는 용어는 억지로 번역하지 않고, 원어를 유지하거나 뜻이 드러나게 풀어 쓴다.

- 점접근 → "dot notation"
- 느슨한 타입 → "타입 선언이 넓어서 타입만 봐서는 값의 의미를 알 수 없는"

### 우리말 대체가 있는 영단어 원어 표기

우리말 대체가 이미 있는 영단어를 산출물 본문에 원어로 두지 않는다.

- exemplar → "모범 사례"
- probe (probe 쿼리·probe로 확인) → "확인용 쿼리 / 확인용 쿼리를 실제 실행해 확인"

### 문장 부호

- — → "라벨 뒤 설명은 콜론(:), 짧은 부연은 괄호, 긴 부연·이유는 문장 분리 (패턴 룰의 em-dash 항목 참조)"

## 패턴 룰 (판독 패스 대상)

grep 으로 잡을 수 없어 문단 단위로 판단한다.

- **"박다" 계열 표현 금지.** 박아넣다/박아라/박는다 → 명시하다/적다/포함하다/고정하다/넣다.
- **한자 혼용 금지.** "백엔드層" → "백엔드 층".
- **미-/무-/비-/역-/저- 접두 조어 금지.** 서술을 접두사로 명사 하나에 압축하지 않는다 ("~가 없다 / ~되어 있지 않다" 서술로 풀어 쓴다). 예: 무영향 → "값이 달라지지 않는다", 미내장 → "(비정상 유저가) 정제되어 있지 않은", 미적재 → "적재되지 않은", 역반영 → "역으로 반영", 비자명 → "코드만으로(설명 없이는) 알 수 없는", 저신뢰 → "신뢰도가 낮은". 같은 패턴의 신조어 전부 해당하고("~성" 명사화 조어 포함: 현행성 → "현행 여부"), 우리말에서 이미 익숙하게 널리 쓰이는 단어(미확인, 비정상 등)는 예외이며 `[미확인]`/`[추정]` 미해결 마커도 유지한다.
- **목록에 없는 압축 조어도 같은 패턴이면 위반.** 위 금지어 목록은 예시 집합이므로, 서술을 한자어 명사 하나에 눌러 담은 신조어는 목록에 없어도 잡는다.
- **"관측"은 대비가 핵심일 때만.** "정의·설계상 존재해야 하는 것 vs 실제 데이터에 나타난 것"의 대비가 문장의 핵심일 때만 쓴다 (예: "정의된 전체 집합이 아니라 운영 중 관측된 값의 집합", 잔존·LTV의 통계 용어 "관측 기간"). 그 대비가 없는 자리에서는 "데이터"·"활동 기록"으로 쓴다 ("관측이 쌓이며 갱신" → "유저 활동 데이터가 쌓이며 갱신").
- **영어 용어는 양방향으로 기존 관행을 지킨다.** 영어가 자연스러운 기술 용어를 억지로 번역하지 않는다 (ROOT 필드처럼 원 시스템의 영어 명칭 유지; dot notation → "점접근", flat → "평탄", cut → "절단", consume → "소비", loosely typed → "느슨한 타입" 같은 축약 직역 금지). 역으로 우리말에서 아직 익숙하지 않은 영어를 발음만 한글로 옮겨 적지 않고, 우리말 대체가 이미 있는 일반 어휘 성격의 영단어(exemplar 류)는 원어로 두지 않는다 (확립된 기술 용어 fan-out, DESCRIBE, comment 등은 예외).
- **명사 나열식 직역투 금지.** "실패 깨움 기반 동시성 적응 복원" 같은 명사 체인 대신 동사가 있는 완전한 문장으로 풀어 쓴다. 화살표(→)로 이은 표기도 앞뒤가 명사 체인이면 해당된다.
- **은유로 압축한 방침·설계 문장 금지.** "확장의 무게는 ~에 싣는다", "~가 감당한다", "~에 승부를 건다", "레포 결"·"주변과 같은 결로"의 "결"(→ "기존 스타일/관행") 류는 실제 메커니즘을 가리므로, 누가/무엇이, 어떤 상황에서, 구체적으로 무엇을 하는지가 문장 안에 드러나게 풀어 쓴다 (예: "사전에 단어를 추가하는 대신 코멘트를 채워서 검색에 걸리게 한다").
- **"구조적 X" 단독 서술 금지.** "구조적 위험/실패/이슈"처럼 무엇의 구조가 어떻게 문제인지 드러나지 않으면 풀어 쓴다 (예: "표 전체 0점 채점 구조에서 오는 위험").
- **"거시/세밀" 명사 단독 금지.** "거시를 겨냥" → "전체 규모를 겨냥"처럼 무엇의 규모/세부인지 명시한다.
- **새 용어는 첫 등장에서 정의.** 새 약칭·개념어를 만들 때는 첫 등장 지점에서 한 문장으로 정의하고, 이후에도 정의 없이 그 단어만 단독으로 쓰지 않는다.
- **논리 관계가 있는 문장을 끊어 쓰지 않는다.** 인과·대비·조건으로 이어지는 내용을 "X한다. Y한다. Z한다."처럼 짧은 단문 연쇄로 끊는 것은 영어 번역투다. 관계가 드러나는 연결어미(~므로, ~지만, ~는데, ~고)로 한 문장으로 잇는다. 예: "이 테이블은 일별로 적재된다. 지연이 있을 수 있다. 조회 시 주의한다." → "이 테이블은 일별로 적재되지만 지연이 있을 수 있으므로 조회 시 주의가 필요하다." 단 서로 독립된 내용까지 한 문장에 욱여넣지는 않으며, em-dash 를 문장 분리로 치환할 때도 분리 결과가 논리 관계 있는 단문 연쇄가 되면 연결어미 연결을 먼저 시도한다.
- **em-dash(—) 를 산출 문서에 쓰지 않는다.** 두 패턴으로 나눠 기계적으로 대응한다:
  - 패턴 (a) 라벨 — 설명 (불릿/원리 머리): 콜론(:)으로 치환한다. 예: "**원리 1 — 정제 판정일 = 값의 기준 날짜.**" → "**원리 1: 정제 판정일 = 값의 기준 날짜.**". 단 볼드 라벨 안에 이미 `=` 나 `:` 가 있어 콜론이 중첩되면 어색해지는 자리는 개별 손질한다.
  - 패턴 (b) 문장 — 부연·이유 (문장 중간의 덧붙임): 길이로 나눠 적용한다. 짧은 부연은 괄호로 ("자동 적용하지 마세요 — 원본 그대로의…" → "자동 적용하지 마세요 (원본 그대로의 적재 상태가 조사 대상입니다)"), 긴 부연·이유는 문장 분리로 ("자동 적용하지 마세요. 원본 그대로의 적재 상태가 조사 대상이며…"). 괄호에 긴 절을 넣으면 오히려 읽기 어려워지므로 길이 기준으로 나눈다.
