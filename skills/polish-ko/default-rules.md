# 한국어 윤문 룰 (플러그인 표준)

이 파일이 korean-polishing 플러그인의 표준 룰 원본이다. 프로젝트 `.claude/korean-polishing-rules.md` 나 개인 `~/.claude/korean-polishing-rules.md` 가 있으면 이 룰에 병합된다 — 형식은 이 파일과 같게 쓴다.

한국어 산출물(문서, 테이블·컬럼 comment, 분석 보고서, PR 본문)은 사람과 후속 AI 에이전트가 그대로 활용하는 자산이다. 기준은 하나다: 처음 읽는 사람과 AI 에이전트가 문장만 보고 의미를 특정할 수 있어야 한다.

## 금지어 목록 (grep 패스 대상)

`금지어 → "대체 표현"` 형식. 스킬의 grep 패스가 이 목록을 파싱해 기계적으로 검색한다.

### 접두 조어 (미-/무-/비-/역- 등)

서술을 접두사로 명사 하나에 압축하지 않는다 — "~가 없다 / ~되어 있지 않다" 서술로 풀어 쓴다.

- 미내장 → "정제가 내장되어 있지 않은"
- 무영향 → "값이 달라지지 않는다"
- 미적재 → "적재되지 않은"
- 역반영 → "역으로 반영"
- 비자명 → "코드만으로(설명 없이는) 알 수 없는"

예외: 이미 익숙하게 널리 쓰여 설명 없이 뜻이 통하는 단어(미확인, 비정상 등)와 `[미확인]`/`[추정]` 미해결 마커.

### 문어체 압축어

- 축자 → "문자 그대로"
- 획정 → "범위를 정한다"
- 봉투 → "감싸는 구조/래퍼(wrapper)"
- 계상 → "집계에 잡힌다"
- 정본 → "SSoT인 ~에서 확인한다"
- 재전사 → "옮겨 적다"
- 규약 → "룰/원칙"
- 병용 → "함께 사용한다"
- 관철 → "(끝까지) 지켜진다"
- 실존 확인 → "실제로 존재하는지 확인"
- 과적용 → "범위를 넘겨 적용"
- 귀속 → "어느 쪽에 속하는지 판정한다"
- 발화(이벤트가) → "기록된다/발생한다"
- 완형 → "완성된 형태"
- 오정렬 → "어긋난다"
- 전칭 → "'모든 ~' 단정"
- 비통일 → "~마다 다르다"
- 소관 → "~가 맡는다"
- 위임 → "~에 맡긴다"
- 준용 → "~와 같은 방식으로 한다"
- 물화 → "todo 항목으로 만들어지다/등재되다"
- 실해 → "실제 피해"
- 정밀화 → "정밀하게 맞추다/다듬다"
- 자명 → "따로 설명하지 않아도(코드만 읽어도) 알 수 있다"
- 잣대 → "기준"
- 정착(표현이) → "이미 익숙하게 널리 쓰이는"
- 음차 → "발음만 한글로 옮겨 적기"
- 산문 → "사람이 문장으로 읽는 글/텍스트" (이 단어는 단순 치환보다, 단어를 빼고 문장을 재구성하는 쪽이 자연스럽다 — 예: "영어 단어를 산문에 두지 않는다" → "영어 단어를 발음만 한글로 옮겨 적으면 뜻이 통하지 않는다")

### 발음만 한글로 옮겨 적은 영어

영어 단어를 발음만 한글로 옮겨 적으면 처음 읽는 사람에게 뜻이 통하지 않는다 — 풀어 쓰고 필요하면 영문을 병기한다. 잘못된 발음 표기도 여기서 잡는다.

- 어노말리 → "비정상(anomaly)"
- 스킴 → "규칙/방식"
- 헝크 → "충돌 구간/변경 블록(hunk)"
- 라인리지 → "리니지(lineage)"

### 확립된 영어 용어의 축약 직역

영어 그대로 쓰는 것이 처음 읽는 사람에게 더 잘 통하는 용어는 억지로 번역하지 않는다 — 원어를 유지하거나 뜻이 드러나게 풀어 쓴다.

- 점접근 → "dot notation"
- 느슨한 타입 → "타입 선언이 넓어서 타입만 봐서는 값의 의미를 알 수 없는"

## 패턴 룰 (판독 패스 대상)

grep 으로 잡을 수 없어 LLM 이 문단 단위로 판단한다.

- **"박다" 계열 표현 금지.** 박아넣다/박아라/박는다 → 명시하다/적다/포함하다/고정하다/넣다.
- **한자 혼용 금지.** "백엔드層" → "백엔드 층".
- **목록에 없는 압축 조어도 같은 패턴이면 위반.** 위 금지어 목록은 예시 집합이다 — 서술을 한자어 명사 하나에 눌러 담은 신조어("~성" 명사화 조어 포함)는 목록에 없어도 잡는다.
- **"관측"은 대비가 핵심일 때만.** "정의·설계상 존재해야 하는 것 vs 실제 데이터에 나타난 것"의 대비가 문장의 핵심일 때만 쓴다(예: "정의된 전체 집합이 아니라 운영 중 관측된 값의 집합", 통계 용어 "관측 기간"). 그 대비가 없는 자리에서는 "데이터"·"활동 기록"으로 쓴다.
- **명사 나열식 직역투 금지.** "실패 깨움 기반 동시성 적응 복원", "군더더기 판정 단위를 문장 → 층위로" 같은 명사 체인 대신 동사가 있는 완전한 문장으로 쓴다("군더더기인지는 문장 단위가 아니라 층위 단위로 판정한다"). 화살표(→)로 이은 표기도 앞뒤가 명사 체인이면 해당된다.
- **은유로 압축한 방침·설계 문장 금지.** "사본은 따로 늙는다", "확장의 무게는 ~에 싣는다", "레포 결"의 "결"(→ "기존 스타일/관행") 류는 실제 메커니즘을 가린다 — 누가/무엇이 어떤 상황에서 구체적으로 무엇을 하는지가 문장 안에 드러나게 쓴다.
- **새 용어는 첫 등장에서 정의.** 새 약칭·개념어를 만들 때는 첫 등장 지점에서 한 문장으로 정의하고, 이후에도 정의 없이 그 단어만 단독으로 쓰지 않는다.
