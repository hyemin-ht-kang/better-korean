# 한국어 작성시 주의사항

## 기본 전제

처음 읽는 사람이나 AI 에이전트가 문장만 보고 의미를 이해할 수 있어야 한다. 낯선 압축어나 어색한 번역어는 내용이 조금 길어지더라도 풀어서 쓰고, 필요하면 원어를 병기한다. 이 요약은 글을 쓰는 시점에 적용하는 원칙이고, 금지어별 대체 표현이 적힌 전체 목록은 polish 스킬의 `default-rules.md` 에 있다.

## 1. 단어 선정 룰

- 영어 단어를 직역해서 한자어 하나로 축약하지 말고, 자연스러운 한국어 표현으로 풀어 쓴다 (예:  "미내장" → "내장되어 있지 않은", "획정" → "범위를 정한다", "현행성" → "현행 여부").
- 영어를 발음만 한글로 옮긴 표현을 쓰지 않고 실제 적절히 대응되는 한국어 단어를 쓰되, 필요시 원어를 병기 (예: "비정상(anomaly)").
- 확립된 영어 용어를 축약해서 직역하지 말고, 원어를 유지하거나 뜻이 드러나게 풀어 쓴다 (예: "dot notation").
- 적절한 한국어 대체 용어가 있는 영단어는 우리말로 쓴다 ("exemplar" → "모범 사례"). 단, 널리 확립된 기술 용어("fan-out")는 예외.
- "박다" 계열 ("박아넣다") 의 표현은 쓰지 않고 맥락에 맞게 "명시하다" / "적다" / "포함하다" 등으로 작성.
- 한자를 혼용해서 쓰지 않는다 ("再시도" → "재시도").
- em-dash (—) 대신 라벨 뒤면 콜론, 짧은 부연설명은 괄호를 사용하되, 길어지면 문장으로 분리.

## 2. 문장을 쓰는 방식

- 명사만 늘어놓은 직역투는 주어와 동사가 있는 완전한 문장으로 쓴다. ("비밀 해제 선점" → "비공개 컨텐츠가 해제될 경우 미리 알림을 차단")
- 문서에 등장한 적 없는 주장을 부정하는 "A가 아니라 B다" 와 같은 대비 표현은 읽는 사람이 이해하기 어려우므로, A 의 언급을 빼고 B 가 성립하는 이유와 결정 자체만을 인과적으로 서술한다. 독자가 실제로 혼동할 두 대상을 구분하는 정의 문장은 예외.
- 의미 없이 개수만 적는 표현은 어색한 영어식 표현이므로 대상 자체를 바로 서술 (예: "기준은 둘이다" → "생성시점과 수정시점을 기준으로 사용한다"). 단, 개수가 근거·제약·결정으로 쓰이거나 전체 규모 파악에 도움이 되면 적는다.
- "A는 B, C는 D" 식의 병렬 구문은 어색한 영어식 표현이므로 항목별 불릿이나 별도 문장으로 정리 (조건 분기도 조건별 불릿으로).
- 무생물을 사람이나 사물에 비유하는 표현을 쓰지 않고, 무엇이 어떻게 되는지 있는 그대로 서술 (예: "링크가 죽는다" → "링크가 끊어진다").
- 은유로 압축한 설계 문장("무게는 ~에 싣는다")은 누가 어떤 상황에서 무엇을 하는지가 드러나게 풀어 쓴다. "구조적 위험"처럼 무엇의 구조인지 빠진 표현도 같다.
- 새 약칭·개념어는 첫 등장에서 한 문장으로 정의한다.
- 분류·비교 기준을 "축" 으로 부르지 않고 가리키는 것을 그대로 쓴다 ("분류 축" → "분류 기준"). x축·시간축 같은 좌표 뜻은 예외.
- 인과·대비·조건으로 이어지는 내용은 짧은 문장으로 끊어 쓰지 않고 연결어미로 자연스럽게 이어서 작성 (예: "X이다. Y한다. Z된다." → ~므로, ~지만, ~는데)
- 병렬 항목은 불릿으로 정리하고, 표의 셀과 불릿 항목은 명사형("건너뜀")으로 마무리한다. 이미 명사형인 어미를 "~다"로 바꾸지 않는다.
